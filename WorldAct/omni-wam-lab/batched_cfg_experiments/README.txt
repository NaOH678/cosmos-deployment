Single-GPU batched CFG experiment, RTX5090/SM120, 2026-10-07

Result: keep existing serial CFG. No useful speed improvement found.
All production code and original resident service were left untouched. No ROS/robot controls.
Authoritative complete results: summary.json, generated by summarize.py.

Five actual saved observations, 5 warmup + 20 timed calls:
  Serial CFG:             P50 441.59 ms, P95 444.14 ms
  GEN B2, split attention: P50 439.06 ms, P95 449.37 ms
  GEN B2, masked B2 attn:  P50 470.49 ms, P95 477.38 ms
All use 4w EMA, CUTLASS FP8, BF16 explicit cuDNN attention, 4 UniPC steps, CFG3.
Scope is observation packet to CPU raw actions, not HTTP or production recording.

Implementation:
  build_candidate.py creates a symlinked source tree with two real copied/edited files.
  batched_cfg_impl.py preserves independently prepared cond/uncond UND K/V and mRoPE.
  Both branch inputs are cast to model dtype as in predict_noise; outputs return sampling dtype.
  GEN hidden tensors combine at B2=[2,3399,2048], 28 layers, once per 4 denoising steps.
  Split mode batches QKV/MLP/output GEMMs while invoking cuDNN separately per text length.
  Masked mode batches cuDNN too, with false entries precisely at uncond 19:140 padding;
  all generated keys remain valid. Branch postprocessing then original CFG/UniPC are retained.
  First measured warmup writes runtime evidence once; it is not repeated in timed samples.

benchmarked runner: benchmark_cfg.py, --batched-cfg --cfg-attention split|masked.
Without --batched-cfg it executes unchanged original serial CFG on the same candidate source.
Optional --save-branches adds one excluded call after measured calls, saving both branches'
video/action predictions at step1 and step4. These are available in results/*/branches/.

Numerical caution:
  Full action and branch errors are in summary.json. Differences already arise at step1.
  Cause is not fully isolated. Do not label it simply FP8 error or prove equivalence from
  a padding test. Current activation scaling is per-token, not whole-batch amax.
  All variants exactly repeat A after B/C/D/E inputs; different observations change output.

Correctness checks:
  CPU 8-case split/masked attention and independent pair-preparation tests reviewed by root.
  test_padding_gpu.py pins actual cuDNN; putting +/-1000 into excluded padding changes output
  by exactly 0. Masked B2 versus trimmed B1 yields max0.00390625 in this small BF16 example.
  GPU test scope is smaller than production attention; it validates masking, not model parity.

B2 allocator peak: 5.42GB allocated / 6.50GB reserved, excludes other resident processes.
Serial allocator peak not captured in the baseline run, explicitly left null in summary.
Earlier masked_corpus included per-request audit I/O; final comparison uses masked_clean.
Prototype remains restricted to B1 WAM inputs, no control/sound/SP/cache-dit, offline only.

Reference principle (official use_batched_cfg):
https://raw.githubusercontent.com/NVIDIA/cosmos-framework/main/cosmos_framework/model/generator/omni_mot_model.py
This is an adaptation for Omni's existing tensor layout, not a claim of byte-for-byte official code.

Reproduce from omni-wam-lab (no robot commands):
OMP_NUM_THREADS=4 CUDA_VISIBLE_DEVICES=0 .venv/bin/python batched_cfg_experiments/benchmark_cfg.py --model artifacts/4w-ema-omni --packet fixtures/observation_01.npz --corpus optimization_20261007/corpus.json --output batched_cfg_experiments/results/retest --first-frame-only --quantization fp8 --warmup 5 --repeat 20 --save-branches
Add --batched-cfg --cfg-attention split or --batched-cfg --cfg-attention masked.
Do not run competing GPU workloads while measuring.

Run conclusions:
  split_smoke: implementation bootstraps and B2 verified, insufficient samples for speed claims.
  masked_corpus: full masked implementation works, slower; superseded by clean audit-I/O version.
  serial_corpus: contemporaneous 5-observation baseline; branch snapshots preserved.
  split_corpus: no useful acceleration; median -2.5ms and P95 worse, output parity unproven.
  masked_clean: full B2 cuDNN mask costs more, no reason to deploy; output parity unproven.
  padding_test: huge invalid pad values excluded by cuDNN, but no whole-model parity proof.
These results only reject these tested implementations as useful acceleration candidates;
they do not demonstrate an architectural speed limit of RTX5090.
