## 本页会用到的指标(先看一眼,后面直接用)

模型的任务:**看着画面,预测盘子里那簇点在接下来 32 帧里怎么动** —— 每个点、每一帧、一个三维位移。

| 指标 | 一句话 | 好的方向 |
|---|---|---|
| **`ADE / zero`** | 采样出来的轨迹,比"预测一动不动"强多少 | **< 1.0 才算赢** ← **判据** |
| `pred/gt` | 动的**"量"**对不对 —— 预测的散布 ÷ 真值的散布 | 越接近 **1** 越好 |
| 逐点余弦 | 动的**"方向"**对不对 —— 每点预测方向 vs 真值方向 | 越接近 **+1** 越好 |
| `共模占比` | 点是"整块一起动"还是"各走各的" | 数据本身是 **0.16** |
| `pf_loss` | 训练侧:速度场拟合得多准(**有地板,门槛 1.0**) | 越小越好,但**别跨配置比数值** |
| 一步 ADE | 训练侧:**只看一步**的估计,比采样轨迹容易得多 | **别拿它当结论** |

几个词的解释:

- **`ADE / zero`** = `all_ade_mm` ÷ `zero_all_ade_mm`。前者是预测轨迹**平均每个点每帧差几毫米**;
  后者是把预测换成"一动不动"算出来的同一个数。**后者只取决于数据**,所以对同一批 eval case
  它是常数,跨 step 可以直接比。
- **`pred/gt` 单独看会骗人**:一堆"幅度对、方向全随机"的噪声,它也等于 1.0。
  所以:**ratio 偏离 1 → 错在"量";ratio≈1 但余弦低 → 错在"方向"。**
- **`共模占比`**:把 410 个点的位移取平均,得到"整体一起移动"的那一份,看它占总能量的比例。
  接近 1 = 整块刚体;接近 0 = 散沙(扇子)。**数据本身是 0.16。**
- **`pf_loss` 的门槛为什么是 1.0**:它是 `|v̂ − (ε − d')|²`,而归一化后 clean 样本 d' 的 std = 1.0。
  所以"完美读出噪声 ε、完全不管位移"恰好得 1.0。**改 `pointflow_displacement_scale` 会挪动这个
  门槛的绝对数值**(改后"预测零"从 ~1.0 变 ~2.0),跨配置比数值没有意义,只看趋势。

## 0. 一句话

**PointFlow 的 clean 样本(点位移)没有归一化就加了单位方差噪声 —— 位移的 std 只有 0.113 m,噪声是
1.0 m,信噪比 1:9。于是 flow-matching loss 的 90% 在度量"噪声复现得准不准",只有 10% 在度量
"点动得对不对"。loss 从 1.0 降到 0.012 是真的,但它不代表分支学会了预测运动。**

采样出来的东西因此是:**一块正确的共模 + 一层逐点各向同性的残差噪声,而残差比信号大 3~7 倍**。
在 `comparison.png` 里,这层残差就是那把"从点簇向外辐射的直线扇子"。

**为什么视频没事(§2.2):** 视频 VAE latent 的 std 是 **0.872** —— 天然单位尺度,信噪比 1:1.1。
**点分支是整条流水线里唯一一个数据比噪声小一个数量级的模态。**

> **证据等级**:尺度失配是**实测**的;`sampler 输出 = 初始噪声缩小 63%` 是**实测**的;
> "改 scale 就能修好"原本是**推断** —— **现已由 §9 的重训判定为真**:每个 eval step 都远好于旧 run,
> 最好成绩 1.10 vs 1.98(单 case)/ 1.343 vs 2.098(14 case 均值)。
>
> **但只解决了一部分。** 预设判据 `ADE/zero < 1.0` 未达到,且有遗留退化(§9.5)。
> **不要读成"问题解决了"** —— 读成"最大的那个原因确认了,还剩一个"。

### 1.3 形状上

把每个点的总位移拆成 **共模**(所有点都一起移的那份)+ **逐点残差**(每个点自己的那份)。
两个读法:

- **共模能量占比** = 共模占总能量的比例。**接近 1** = 所有点像一块刚体一起动;**接近 0** = 散沙。
  这批数据本身是 **0.16**。
- **逐点方向余弦** = 每个点预测的运动方向 vs 真值方向,夹角余弦,取中位。
  **+1** = 全都朝对的方向;**0** = 方向全乱;−1 = 全反。只看方向,不看长度。

```

```

另外两侧的位移**都与帧号近似线性**(相关 0.95~0.98),因为 rectified flow 的路径
`x_σ = σ·ε + (1−σ)·x_0` 对 σ 本来就是线性的 —— **"直线"本身不是异常,"各自朝不同方向"才是。**

## 2. 根因

### 2.1 代码

`cosmos_framework/model/generator/pointflow_training.py:10-26`:

```python
def pointflow_add_noise(clean, sigmas, *, scale=1.0, generator=None, epsilon=None):
    ...
    target = clean.displacement.float() / scale          # ← scale = 1.0
    if epsilon is None:
        epsilon = torch.randn(target.shape, ...)         # ← std = 1.0
    per_point_sigma = sigma[clean.inputs['point_batch']][None, :, None]
    state = PointFlowNoised(per_point_sigma * epsilon + (1 - per_point_sigma) * target,
                            epsilon, epsilon - target, sigma)
```

`cosmos_framework/configs/base/defaults/model_config.py:76`:

```python
pointflow_displacement_scale: float = 1.0  # meters per model unit; fixed train/inference scale
```

**`scale = 1.0` 意味着 `target` 就是米制原值。** 而实测:

```
target  (点位移) per-element std   =  0.113 m
epsilon (噪声)   per-element std   =  1.000 m
                                     ─────────
                                     信噪比 1 : 9
```

**clean 样本比噪声小一个数量级。**

### 2.2 关键对照:视频那一路是单位尺度

同样的 rectified flow 机制,视频分支跑得起来。区别在哪?**量一下视频的数据尺度**
(`vae_window_latents/*.npy`,bfloat16 位模式存在 uint16 里,解码后统计):

```
视频 latent          std = 0.872      ← 天然单位尺度
采样初始噪声          std = 1.000
                    ─────────────
                    信噪比 ≈ 1 : 1.1     ✅
```

对比:

| | 数据 std | 噪声 std | 信噪比 |
|---|---|---|---|
| **视频**(latent) | 0.872 | 1.0 | **1 : 1.1** |
| **点**(位移) | 0.113 | 1.0 | **1 : 9** |

**视频变分自编码器的 latent 本来就是归一化的,所以视频分支的 flow 是良态的。点分支没有这一步
—— 它是整条流水线里唯一一个数据比噪声小一个数量级的模态。** 这是"为什么视频行、点不行"的
直接答案,而且不是推断,是量出来的。

> 解码方式(供复核):`vae_window_latents/<name>.npy` 存的是 **bfloat16 的位模式塞在 uint16 里**,
> 见 `singlerighthand_raw_dataset.py:531 _read_window_latent`。
> `f32 = (raw.astype(np.uint32) << 16).view(np.float32)`

### 2.3 这个配置本来的用途

注释写得很清楚:`meters per model unit; fixed train/inference scale` —— **它就是为归一化准备的**,
而且两侧管道都已接通:

```python
# 训练侧  pointflow_training.py:17
target = clean.displacement.float() / scale
# 采样侧  pointflow_sampling.py: 最后一行
return state * scale
```

**只是值被留在了 1.0。**

## 3. 机制:为什么这必然产出"直线扇子"

### 3.1 loss 在度量什么

`v_target = ε − x_0`。代入实测尺度:

```
|ε| ~ 1.00        |x_0| ~ 0.113
```

`v_target` 的 **90% 是噪声**(见 §2.1)。于是:

```
"预测零"          →  loss ≈ 1.0        (噪声自己的能量)
模型现在          →  loss = 0.012      →  RMSE = 0.11
真正的位移信号    →  std  = 0.113
```

**速度的残差(0.11)和整个位移信号(0.113)一样大。** loss 降低了 98.8%,但降的绝大部分是
"把噪声复现出来"那一项 —— 那一项和"点会不会动"基本无关。

### 3.2 采样输出是什么

采样从 `ε`(std 1.0)出发,积分到 clean。模型学到了什么?**它学到了"把噪声按一个常数比例缩掉"**:

```
实测预测 std 均值  0.370
1 − 0.370 = 0.630   →  把初始噪声等比缩小 63%
```

这解释了 §1.2 的两点:幅度≈常数、与目标只弱相关。

而 §1.3 的"扇子"也直接对上了:输出 = 初始噪声 × 常数,而初始噪声是**逐点独立**的
`randn`。在 rectified flow 里 `x_σ` 对 σ 线性 ⇒ **每个点沿自己的方向匀速离开锚点 ⇒ 直线扇**。

### 3.3 为什么"更多采样步数"救不了

步数只影响积分的离散化误差。**这里错的是速度场的终点,不是积分路径** ——
所以 16 vs 32 步只差 5%,σ-shift 修了也没用(`fit005_analysis` §6、§8)。两条都被证伪,
现在有了统一解释。

## 4. 为什么训练 loss 看不出来

`train/pointflow_loss` 从 0.237 单调降到 0.012(`fit005_analysis` §5),看起来完美收敛。
但**这个 loss 的 90% 权重在噪声上**,所以:

| | loss | 说明 |
|---|---|---|
| 预测零 | ≈ 1.0 | 噪声能量 |
| **把噪声复现得很好、位移全错** | **可以低到 0.01 量级** | **就是现在** |
| 位移对了但速度场有 30% 误差 | 明显更高 | 反而"更差" |

**⇒ "loss 低"不能作为分支有效的证据。** 这个跑 8300 步的 loss 曲线,和它的 ADE 曲线
(210 mm @1500 → 483 mm @8000,而"预测不动"基线是 129 mm)是**可以同时成立的**。

## 6. 修法

### 6.1 原则:每个模态归一到**它自己的**单位尺度

**这不是"标准做法"这么含糊的说法 —— 这正是本仓库既有的约定,而且写在注释里。**

| 模态 | 归一化机制 | 归一化后 std |
|---|---|---|
| 视频 | VAE 编码(`Wan2pt2VAEInterface`) | **0.872**(实测,§2.2) |
| action | `quantile_rot` / `ActionAsinhNormalization`(q01/q99 → ±1) | ~1(设计目标) |
| **点** | **无** | **0.113** ← 唯一的例外 |

`action_processing.py:85` 里 `ActionAsinhNormalization` 的注释把**理由**说得很直白:

> The `asinh(1)` factor keeps q01/q99-style unit deviations near ±1 while mapping
> 100-250× outliers to single-digit targets **instead of exploding the flow-matching loss**.

**也就是说:仓库早就知道"clean 样本的尺度要和单位噪声对齐,否则 flow-matching loss 会失控"。
点分支只是漏了这一步。**

### 6.2 所以:**不要**把 video 和 action 放在一起归一化

共用的东西是**目标尺度(单位方差)**,不是**变换本身**。

- 视频的"1"是 VAE latent 空间的 1,action 的"1"是关节角/末端位移的 1 —— 两者单位不同,
  **一个共享的仿射变换没有意义**。
- 每个模态有自己的自然单位和分布,必须由自己的归一化器映射到单位尺度。**仓库现在就是这么做的。**

真正需要跨模态对齐的是**另一件事:loss 的相对权重**。那由
`loss_scale=10`(视频)/ `action_loss_weight=10` / `pointflow_loss_weight=1` 负责。

> ⚠️ **别把这两件事混起来。** 旧的待办里有"提高 `pointflow_loss_weight`"这一条 ——
> 那正是用权重去补偿一个尺度 bug。**不会有用**,因为问题不是分支权重太低,
> 而是它的 loss 根本不在度量位移。**先归零尺度,再谈权重。**

### 6.3 怎么做:三个选项

| 方案 | 做法 | 代价 | 评价 |
|---|---|---|---|
| **A. 全局标量** | `scale` = 训练集全部有效位移元素的 std | **零代码** | **✅ 推荐**,先验证机制 |
| B. 按 episode | 每个 episode 一个 scale,随批次传进去 | 要改 batch/采样两侧 | 尺度差 8 倍时更贴合,机制验证后再考虑 |
| C. 按窗口 | 用该窗口自己的位移统计量 | — | ❌ **不能用** —— 用了未来标签,推理时拿不到 |

**A 虽然粗糙,但不含任何泄漏**:它是离线算好的固定数据集统计量,和 action 的 q01/q99
是同一类东西 —— **推理时随时可用,不是"仅训练可用"的权宜之计。**

### 6.4 具体改哪个值

**实测值(2026-09-14,10 个 episode × 8 窗口,`select=5%` 与训练一致):**

```
n = 2,528,250 个有效位移元素
均值  +0.00361    q01 −0.23252    q50 −0.00049    q99 +0.19973
std    0.08390    |v| p50 0.02016   p99 0.31484   p99.9 0.74817   max 8.6111
                                                                    ↑ 单个元素,追踪离群点
```

**候选统计量与取舍:**

| 统计量 | 值 | clean/噪声 | 说明 |
|---|---|---|---|
| **`std`** | **0.08390** | **1.000** | **✅ 取这个** —— 唯一**直接匹配单位方差噪声**的 |
| `(q99−q01)/4.6524` | 0.09291 | 1.107 | "稳健 std":高斯下等于 std,抗尾部 |
| `(q99−q01)/2` | 0.21613 | 2.576 | action 归一化器的约定(q01/q99 → ±1) |

**为什么用 `std` 而不是 q01/q99:**

1. **噪声是 std=1.0 的高斯,精确匹配它的是二阶矩。** q01/q99 → ±1 的约定对高斯分布等价于
   除以 2.33σ,会留下 `std ≈ 0.43` —— 而这里用 `(q99−q01)/2` 得到的 0.216 让 clean std 只有
   0.39,即 2.6 倍错配。
2. **尾部没有污染 std。** 实测 `std / robust = 0.90 < 1` —— **分布比高斯还轻尾**。
   8.6 m 那个极值虽然大,但在 253 万个元素里对 std 的贡献 < 1%。
   (轻尾的原因:位移是物理有界的量,而且 t=0 那一层恒为 0。)
3. 三个候选**都能**修掉现在 12 倍的错配,`std` 只是其中最干净的一个。

```python
# cosmos_framework/configs/base/experiment/action/posttrain_config/action_policy_singlerighthand_edge.py
model_config["rectified_flow_training_config"]["pointflow_displacement_scale"] = 0.0839
```

> **✅ 已于 2026-09-14 应用**(带完整注释,含复现命令)。已解析验证:
> `cfg['model']['config']['rectified_flow_training_config']['pointflow_displacement_scale']` → `0.0839`。
> 该字段属于 `RectifiedFlowTrainingConfig`(`model_config.py:76`),与 `loss_scale` 同层。

**不需要改代码** —— 训练侧 `target = displacement / scale`(`pointflow_training.py:17`)、
采样侧 `state * scale`(`pointflow_sampling.py` 末行)都已就位,改的只是这个数。

> **为什么不是 eval 那批算出来的 0.113**:eval 的 14 个 case 是**故意挑高运动窗口**的

### 6.6 需要注意

**① 尺度是均匀的 —— 单个全局值够用。** 均匀采样 80 个窗口,逐 episode 的 std:

```

episode_0017  0.0654      范围 0.0553 ~ 0.1536
episode_0018a 0.0691      倍数 2.8×
```

**只差 2.8 倍,不是 8 倍** —— 之前说的 8 倍是 eval 那 14 个 case 算的,而它们是**故意挑高运动窗口**的,
把分布拉宽了。按训练真正看到的分布,**一个全局常量够用**,不需要按 episode 归一化。

**② 约 9% 的窗口一个点都没有。** 80 个窗口里 **7 个 `displacement_n = 0`**、8 个 `voxels` 低于
退化阈值。`prepare_window(..., allow_empty=True)` 在锚点帧有效点不足 3 个时返回空。
**这是数据侧既有的问题(与 `select_motion_fraction` 无关)** —— 空样本在训练里没有 point 监督,
在 eval 里会直接抛错。**值得单独查**,但不阻塞本次修复。

**③ 有 3718 mm 的追踪离群点。** 窗口级 `motion_max` 最大到 3.7 米 —— 和早先 top-K 体素方案
踩到的同一类噪声(见 `pointflow_motion_selection_20260914.md`)。它对 **std 的影响很小**
(2.5M 个元素里的极少数),但说明选点仍会带上离群点。

**④ 两侧尺度必须一致。** 采样侧 `sample_displacement` 的初始噪声是 `torch.randn`(std 1,
**模型单位**),输出 `state * scale` 才回到米。改 `scale` 两侧同时生效,不用动代码。

**⑤ 旧 checkpoint 不能续训** —— 归一化变了,`target` 和模型学到的尺度都变了。

### 10.2 初步推断(**不是结论**)

#### I1 不止采样一个问题

依据 P2:`一步 ADE` 与采样器无关,却和 `pf_loss` 同时停在 ~500 步、停在 0.45。
**⇒ 拟合这条路上也有天花板。**

参照:这个点刚性连在夹爪上,而且动作是**真值**给它的 —— 直接估计本该接近完美。0.45 差得远。

#### I2 ⚠️ 撤回:"低 σ 没训练"

**我最初按 P3 的表象读作"高 σ 学会了、低 σ 没学"。这个读法是错的。**

原因在 `v = ε − d'` 里 ε 的表达式:

```
ε = (x_σ − (1−σ)·d') / σ
                    ↑  这个 1/σ 是放大器
```

```
σ = 0.10    d' 上 10% 的误差  →  v 上 100% 的误差(放大 10 倍)
σ = 0.83    d' 上 10% 的误差  →  v 上  12% 的误差
```

⇒ **低 σ 桶的 loss 地板天生就高。** 从 1.399 降到 1.141 可能已经贴着地板,和"学没学会"无关。
**两个桶的 loss 数值不可直接对比**;用"降了几倍"判断哪一档学得好,是错的。

**连带后果**:§9.6 那个"给 point 分支单独 σ 调度"的方案,**依据被撤回** —— 它建立在"低 σ 没训练"之上。

#### I3 监督宽度不是瓶颈(但归因不清)

依据 P1:只监督 1 个点、点云仍完整时,**采样轨迹和全监督几乎一样**(早期贴合,后期略好)。
⇒ "一个簇 token 要描述很多点"这件事,**不是采样轨迹坏的原因**。

⚠️ **但 sup1 比 scale0084 多两个变量**(护栏 `min_voxel_members=3` 和单点监督),
所以"后期更好"**归因不到具体是哪一个**。要拆开得再跑一版。

#### I4 σ 路线被双重削弱

- I2:低 σ 桶"没学会"的判断不成立
- P5 反面:**action 在同一个 σ 下能训好** ⇒ "共享视频 σ"本身不必然是病

⇒ **"给点分支换 σ 调度"这条路,现在既没有证据支持、也没有合理的机制解释。** 暂时搁置。

#### I5 现在还剩下什么

按可疑度排:

| # | 假设 | 支持它的现象 | 怎么证伪 |
|---|---|---|---|
| **1** | **低 σ 那几步是断点**(机制是 `1/σ` 放大,不是"没训练") | P6(采样最后一步正好在那)+ P2(整体 loss 停) | **eval 里给一串 σ 各算一次一步估计**,看从哪个 σ 开始崩 |
| 2 | 求解器 | P4 只测了 step 20,方向对但幅度小 | 训到 step ≥1000 再看 A/B |
| 3 | 拟合容量(容量 / LR / 条件通路) | P2 的天花板 | 加容量或换更大 codec 试 |
| 4 | 数据里的 artefact | 占 25~46% 的 loss(§6.5),且不可学 | 用新数据(P6 显示已解决)复跑 |

**假设 1 优先**,因为:它是纯测量、不用改训练、而且判据明确。

> **又一次:拿单个 eval 点当信号。**
>
> 教训(与 §12.4 同源):**任何跨 step 或跨 run 的比较,先确认那条曲线是平滑的。**

#### J3 为什么"点多了反而学不好"—— 机制

**不是"信息变少",是"梯度被少数点劫持了"。**

```
普通点    |d'| ≈ 0.1   →  loss 分量 ≈ 0.01
最快的点  |d'| ≈ 1     →  ≈ 1        (100 倍)
artefact  |d'| ≈ 19    →  ≈ 353      (35000 倍)
```

**均值 loss 里没有"按信息量分配"这回事** —— 一个 `|d'|²=353` 的点,
在梯度里的分量等于 35300 个普通点。**而 artefact 又不可学**(运动是追踪失败,视频里没有线索),
所以那部分 loss 永远降不下去,还一直在推梯度。

⇒ **监督 410 个点 ≈ 监督那 20 个最快的点,其中混着不可学的 artefact。**

**但也有一层反直觉**:`sup1` 的点云**仍是 410 个点** —— encoder 和注意力完全没变,
变的只是"哪些点算 loss"。所以这个效应**纯粹来自 loss 的加权**,不是架构。

#### J4 ⚠️ 归因还没拆干净

`sup1` 比 `scale0084` 变了**两个**变量:

```
1. 护栏 min_voxel_members=3       →  换掉了 cloud 里的 artefact 点
2. 单点监督 supervise_cluster_n=1  →  loss 只算 1 个点
```

**J3 讲的两层机制分别对应这两个改动,但哪个贡献更大没有证据。**
（同 §10.2 的 I3 是同一个混淆,当时是对 sup1 vs scale0084 的早期数据说的。）

## 12. σ 扫描:一个我踩了两次的坑(2026-09-15)

§10.4 的 I5-1 假设"**采样器的断点在低 σ**"。为此加了 `pointflow_sigma_scan`
(`omni_mot_model.pointflow_sigma_scan`,开关 `POINTFLOW_SIGMA_SCAN=true`),量的是:

```
x̂₀(σ) = x_σ − σ · v̂        对 σ ∈ {0, 0.05, 0.1, 0.2, 0.3, 0.5, 0.7, 0.9, 0.99} 各算一次
误差 = |x̂₀ − d'|            除以 |d'|(即 metrics 里的 pointflow_sigma_scan_zero)
```

**初始噪声只抽一次、所有 σ 复用**,否则每个 σ 换一份噪声,扫出来的差异会混进噪声实现的不同。

### 12.1 现象:原始曲线

`pointflow_sup1_unipc-scan`(UniPC-4,护栏 + 单点监督):

```
σ        0     0.05    0.1     0.2     0.3     0.5     0.7     0.9     0.99
step 200  0.000  0.066   0.130   0.256   0.378   0.605   0.844   1.090   1.221
step 400  0.000  0.067   0.130   0.244   0.342   0.499   0.637   0.817   0.920
step 600  0.000  0.064   0.124   0.225   0.304   0.396   0.471   0.637   0.734
step 700  0.000  0.066   0.127   0.231   0.312   0.410   0.481   0.612   0.691
```

(`σ=0` 那列的 `0.000` 是**退化的**:σ=0 时 `x_σ` 就是答案,`x̂₀ = x_σ − 0·v̂`,没经过模型。**别读它。**)

**整条曲线都在下移,高 σ 端降得最多**(σ=0.99:1.221 → 0.691,降 43%)。

### 12.2 陷阱:**这个绝对数不能跨 σ 比较**

**"σ 越小数字越小"看起来像"低 σ 学得最好"。这是假的。**

原因:**低 σ 时不用模型也能拿到好分数。** 如果模型什么都不做(`v̂ = 0`):

```
x̂₀ = x_σ = σ·ε + (1−σ)·d'
误差 = |x_σ − d'| = σ·|ε − d'|
```

**输入里本来就含着 `(1−σ)` 份的答案,σ 越小这份答案越完整。** 所以"输出零速度"的分数**随 σ 单调下降**:

```
trivial(σ) = σ · E|ε−d'| / E|d'| = 1.414 σ        (ε、d' 各分量 std = 1)
```

减掉它才看得出模型的真实贡献:

```
σ        "输出零速度"   实测(step 700)   实测 / trivial
0.05       0.071           0.066             0.93     ← 模型几乎没比"啥都不做"好
0.1        0.141           0.127             0.90
0.2        0.283           0.231             0.82
0.3        0.424           0.312             0.74
0.5        0.707           0.410             0.58
0.7        0.990           0.481             0.49
0.9        1.273           0.612             0.48
0.99       1.400           0.691             0.49     ← 模型好 2 倍
```

**⇒ 模型的真实本事只在【高 σ】看得出来。低 σ 那个漂亮的 0.13 是输入送的。**

### 12.3 所以 §10.4 的 I5-1 **不能这样判**

**"低 σ 数字最小 ⇒ 低 σ 最准 ⇒ 断点不在低 σ"—— 这个推理链是断的**,因为那条曲线里
混着一个随 σ 变化的平凡基线。

**I5-1("断点在低 σ")既没有被证实,也没有被证伪。** 它需要一个减掉平凡基线后的量才能判。

### 12.4 方法论教训:**同一个坑我踩了两次**

| | 第一次(§10.4-I2) | 第二次(本节) |
|---|---|---|
| 被比较的量 | σ 分桶的 **loss** | σ 扫描的 **ADE** |
| 为什么不可比 | 低 σ 时 `1/σ` 放大 d' 的误差 | 低 σ 时输入自带 `(1−σ)` 份答案 |
| 共同点 | **基线本身随 σ 变,我却拿绝对数当能力** | 同 |

**这个坑代码注释里早就写过**,`pointflow_ade` 的 docstring:

> Note that a *velocity* of zero is not that baseline: it leaves `x0_hat = x_t`,
> which is dominated by the noise just added.

**—— 说的就是这件事,我还是踩了。**

**规则**:任何按 σ 分层的量,必须**同时报出该层的平凡基线**,否则不要跨层比较。

### 12.5 顺带一个观察:4 步的采样网格**根本不去低 σ**

`shifted_sigmas(4, shift=5)` 的节点:

```
σ = 1  →  0.938  →  0.833  →  0.625  →  0
                                    ↑
                      最后一次问模型在这里,然后一步跳到 0
```

**4 步 UniPC 从不在 σ < 0.625 处评估模型。**

对照 16 步 Euler:`σ = 1, 0.987, …, 0.25, 0` —— 至少走到 0.25。

**两条路的差别可能不在求解器的阶数,而在网格覆盖。** 这一条还没有对照实验。

## 13. 指标怎么算的,以及一次记录上的更正(2026-09-15)

### 13.1 ADE / FDE 的定义

`pointflow_visualize.py:129 trajectory_metrics`:

```python
error = np.linalg.norm(pred - gt, axis=-1)              # 每个(帧,点)一个三维欧氏距离,单位米
future = valid[1:]                                      # 跳过 t=0
all_ade_mm = error[1:][future].mean() * 1000            # ADE:全程平均
all_fde_mm = error[-1][valid[-1]].mean() * 1000         # FDE:只看最后一帧
```

**三点:**

1. **`pred` 和 `gt` 都是"相对锚点帧的位移"**,不是绝对坐标。
2. **跳过 t=0** —— 锚点帧两者按定义都是 0,不跳过会把误差稀释(代码注释:`no t=0 dilution`)。
3. **`zero_*` 是同一函数把 `pred` 换成 `np.zeros_like`** —— 即"预测一动不动"。它只取决于数据,
   所以对固定的 eval case 是常数(实测 `zero_all_ade_mm` 中位 = **105.2 mm**,跨所有 step 不变)。

**⚠️ 那个 `valid` 是 `targets["valid"]` —— 被 `supervise_cluster_n` 掩过的那个。**
所以 `sup1` / `sup1_unipc` 的 ADE **是在 1 个点上算的**(14 个 case,每 case 那 1 个被监督的点)。

### 13.2 除不除 `zero`:两种聚合,而且差得不小

**除的理由**:跨 case 可比(各 case 位移幅度 53mm ~ 963mm,直接平均会被大位移的 case 主导);
`1.0` 有固定含义(比不动强/弱);跨 run 可比。

**不除的理由**:丢了绝对尺度;`zero` 小的 case 比值不稳。

**但更要紧的是聚合方式有二义性** —— `sup1_unipc` @step 10000:

```
ADE 均值        73.6 mm
ADE 中位        37.3 mm
zero 中位      105.2 mm
─────────────────────────
ratio of means  mean(ADE)/mean(zero) = 73.6/105.2 = 0.70
mean of ratios  mean(ADE_c/zero_c)                = 0.547
                                                    ─────
                                                    差 0.15
```

> ⚠️ **本文此前所有 `ADE/zero` 报的都是 `mean of ratios`(0.547),但没有注明。**
> **这是个记录漏洞** —— 两个数差 0.15,足以改变"好多少"的判断。

**⇒ 从现在起两个都报。**

### 13.3 一次更正:`幅度比` 的帧选择错了

本文 §12 之后我曾据一张图得出"幅度比卡在 1.2、偏大 21%、纹丝不动",并由此推断
"有一条通道只传过来方向、没传过来量"。**那个结论要撤回。**

**原因**:我当时自己算的 `幅度比` 用了**固定的第 32 帧**:

```python
P = |flow[-1,i] - flow[0,i]|        # ← 第 32 帧
```

**而很多 case 的第 32 帧是无效帧**,那里 `flow_gt` 是 0(未填值),`flow` 是预测的残留。验证:

```
case       有效帧  valid[32]  gt[32]范数   最后一个有效帧 → 那里的位移
train_00     4      False      0.0mm       第 4 帧  →  570.7mm
val_04      22      False      0.0mm       第 22 帧 →  530.9mm
val_09      22      False      0.0mm       第 22 帧 →  127.5mm
val_00      15      True     167.3mm       第 32 帧 →  167.3mm
```

**⇒ 那 5 个 "`|gt| = 0`" 的 case 不是"点出去又回来",是那一帧没数据。**

改成"最后一个有效帧"之后:

```
错误版(固定第 32 帧):   UniPC 1.21   Euler 1.32     看似永久偏大
正确版(末个有效帧):     UniPC 1.06   Euler 1.06     基本校准,而且两条都在往 1.0 靠
```

**⇒ 撤回"幅度比是硬伤"的判断。** 幅度比是收敛的。

**这个坑和 §12.4 那两条同源**:用了一个"看起来对、其实在该处无定义"的量去比较。
