# FK 总结 1：两个训练条件错误 —— 噪声尺度 与 σ 同步

> **这是 FK 问题总结系列的第 1 篇。** 下一次总结请接着编号：`fk_summary_2.md`、`_3` …
> 系列约定：每篇记录「现象 → 根因 → 修复 → 验证数据 → 排除过的假设」，
> 尤其是**排除过的假设要写全** —— 那部分最省下一次的时间。

> 2026-09-20 定稿。这两个问题分别让 FK 的 eval 读数停在 **3~24** 和 **0.6~3.3**，
> 修完分别是 **0.7~2.3** 和 **0.11~0.55**。两者都**只改训练，不改 eval**。

这份文档记录两件事：

1. **噪声尺度与位移尺度不统一**（`fk_displacement_scale` 用了错的值）
2. **手部动作的噪声档位与视频强行绑定**（eval 的条件在训练里概率为零）

两个问题**互相掩盖**：第 1 个不修，第 2 个的表现会被淹没在噪声里；第 1 个修完，
第 2 个才暴露出来。所以文档按发生顺序讲。

---

## 第 0 节：读之前需要的三个概念

不然后面看不懂。

### σ（噪声档位）

一个 0~1 的数，表示数据有多"脏"：

- **σ = 0** → 干净、真实的原始数据
- **σ = 1** → 纯随机噪声，什么都不剩

模型的工作是：**给一个"某档脏"的数据，说出"干净的样子"**。前向过程写成：

```
x_σ = σ · ε + (1 − σ) · 干净真值
```

其中 `ε` 是标准高斯噪声（每个元素方差为 1）。

### scale（尺度）

上面那个公式里，**`ε` 的大小是 1，所以"干净真值"也必须是 1 左右的量级**，
否则两项根本没法比。`scale` 就是"真值要除以多少才能变成 1 左右"：

```
模型空间里的真值 = 物理真值(米) / scale
```

FK 的标签直接存的是**米**，手的位移约 **0.075 米**，而噪声是 **1** —— 差 13 倍。

### eval 怎么测

FK 的 eval 不是"完整生成"，而是**条件拟合诊断**：视频固定住，**只采样手部动作**。
原因是完整采太慢、而且视频生成本身的误差会混进手的测量里。

所以 eval 会问一个训练里可能存在、也可能不存在的条件组合 —— 这正是第 2 个问题的来源。

## 第 1 个问题：噪声尺度与位移尺度不统一

### 现象

`train/fk_ade_mm` 一路降到几十毫米（模型在训练分布上很准），但 eval 的
`ratio_to_zero` 始终在 **3~24**（远大于 1，也就是**比"猜手不动"还差**），
而且**越训越差**。

### 根因

`fk_displacement_scale` 从点云那条线移植时**只搬了代码，没搬这个值** ——
它留在了配置默认值 **`1.0`**。

而点云孪生在 `action_policy_singlerighthand_edge.py` 里**专门覆盖了它**：

```python
model_config["rectified_flow_training_config"]["pointflow_displacement_scale"] = 0.0839
```

注释写得很清楚：

> Every other modality in this pipeline is already **unit-scale** — the video VAE
> latent measures std 0.872, and the action is normalised by `quantile_rot` — so
> this restores the convention rather than introducing a special case.
> ... A std rather than a q01/q99 span, because **the noise is unit-variance Gaussian**.

**约定是：干净目标必须和单位方差的高斯噪声同尺度。FK 违反了它。**

### 错在数值上意味着什么

实测 FK 位移的 per-element std = **0.074450 米**（10 episode、26,522,496 个元素）。
所以模型空间里：

| | 大小 |
|---|---|
| 干净真值 | 0.0745 |
| 噪声 ε | 1.0 |
| **比值** | **13.4 ×** |

信号的"信噪交叉点"（`(1−σ)·0.0745 = σ·1.0`）落在：

| scale | 交叉点 σ | 含义 |
|---|---|---|
| **1.0（错）** | **σ ≈ 0.069** | σ 只有小于 0.07 时信号才占主导 |
| **0.0745（对）** | **σ = 0.5** | 标准 RF 的情形 |

而训练的 σ 分布（`waver` 经 `shift=5` 扭曲）**43.8% 的质量在 σ∈(0.8, 0.9)、
22.1% 在 (0.9, 1.0)**。在 σ=0.83 处，位移只占整个状态标准差的 **1.5%** ——
**模型几乎全程在学"预测噪声"，真正有用的信号被稀释了 13 倍。**

采样器的 σ 网格 `[1.0, 0.9375, 0.8333, 0.625, 0.0]` 是按单位尺度校准的，
每一个节点都深埋在噪声主导区。

### 修复

```python
model_config["rectified_flow_training_config"]["fk_displacement_scale"] = 0.074450
```

数值来源（可复现）：

```bash
python tools/scan_fk_displacement_scale.py
```

该工具**自校验**：它同时打印"每窗口平均关键点位移范数"（实测 95.8 mm），
这正是训练日志里的 `train/fk_zero_ade_mm`（54~123 mm）。两者对不上就说明
滑窗枚举和训练不一致，那个 std 不能信。

### 验证

同一步数（iter 1000）对比，`ratio_to_zero` 越小越好：

| 用例 | 修复前 | 修复后 |
|---|---|---|
| train_00 | 2.97 | **0.71** |
| train_01 | 17.24 | **1.58** |
| val_00 | 2.63 | **0.71** |
| val_01 | 24.10 | **2.32** |

### 连带影响

- **旧 checkpoint 不能续训**：target 和分支学到的 scale 都变了
- 改完 loss 的**读数会变大**、"猜不动"基线约翻倍 —— **只看 ADE 对零基线，别看 loss 值**
- **选点一变就要重新测**：scale 是"数据选择"的属性，不是模型的属性

### 防复发

`cosmos_framework/configs/base/experiment/action/posttrain_config/fk_displacement_scale_test.py`
断言配置值与实测 std 的比值落在 2× 内。**已验牙**：改回 `1.0` 时报
`比值 = 13.432，容差 2.0x` 并以退出码 1 失败。

## 第 2 个问题：手部的 σ 与视频强行绑定

### 现象

第 1 个问题修完后，eval 好转了（0.7~2.3），但**仍然在 1 附近徘徊，而且随时间恶化**：

| step | train_00 | train_01 | val_00 | val_01 |
|---|---|---|---|---|
| 500 | 0.76 | 1.31 | 0.77 | 1.89 |
| 2000 | 0.65 | 1.85 | 0.69 | 2.59 |
| 10000 | 0.60 | 2.60 | 0.64 | 3.33 |

`zero` 基线小的两个 case（手移动少的）**一路变差**。

可视化上：**预测的 21 个点很散、没有手型**，而且越训越散。

量化（预测点绕质心的散布 vs 手型本身的尺度）：

| step | 手型尺度(GT) | 预测散布 | 误差/尺度 |
|---|---|---|---|
| 500 | 10.7 mm | 21.9 mm | 2.0 |
| 10000 | 10.7 mm | 49.4 mm | **4.6** |

**误差是手型本身的 2~5 倍 → 细节完全被淹没，看上去就是一团散点。**

### 根因

机制链（每一环都有代码或数据佐证）：

1. **训练时手部动作与视频共享同一个 σ。**
   `fk_add_noise(gen_data_clean.fk, sigmas, ...)` 里的 `sigmas` 就是 vision 的
   （`fk_add_noise` 的注释明确要求 "one shared video sigma per sample"）。
   所以训练样本里，"加噪的手"永远搭配"同一个 σ 加噪的视频"。

2. **eval 的条件组合在训练分布中概率为零。**
   eval（`_fk_fitting_context`）打包**干净视频**（连未来都是真值），
   手却从纯噪声出发 —— "干净 video + 加噪手"，训练中从未出现。

3. **模型学会了捷径**："视频干净 ⇒ σ≈0"。而 σ=0 时 `x0_hat = x_t`，
   即**把输入原样当答案** —— 于是输出 = 初始噪声 × 系数。

4. 这解释了全部现象：预测的 21 个点**沿各自的初始噪声方向飞出**，
   互不相干、不成手型；训练指标一路降（训练时条件匹配），eval 单调恶化。

**关键认知：eval 给干净视频本身不是 bug —— 它对应一个真实的部署场景
（"只有观测、没有未来视频时预测手部运动"）。错的是训练从没覆盖这个条件。**

点云那条线在 **2026-09-19 独立发现并修复了同一个问题**，文档见
`WorldAct-cosmos3-edge-droid-sft/docs/pointflow_per_point_tokens_20260919.md`。
它的原话：

> **eval 的条件组合在训练分布中概率为零。**
> `comparison.png` 呈**直线扇形炸开**：所有点的预测位移沿各自初始噪声方向飞出，
> 即"输出 ≈ 缩放后的初始噪声"。

—— 与 FK 的"散乱、没有手型"是同一现象。

### 修复：解耦 σ，只改训练

新增 `rectified_flow_training_config.independent_fk_schedule`（默认 `False`）。
开启后每个训练 step，手部动作**从 vision RF 采样器独立抽一个 σ**
（`_get_train_noise_level_fk`）。

- **边缘分布不变**（同 waver/shift），只切断"手 σ ≡ 视频 σ"的耦合
- "干净/低噪视频 + 加噪的手"从此出现在训练分布中
- **eval 一行未改** —— 它是测量仪器；修复发生在训练侧，让 eval 的条件变成分布内
- **模型形状不变**，可从旧 checkpoint 直接续训验证

这样训练同时覆盖两种部署形态：

| 训练里的组合 | 对应场景 |
|---|---|
| 视频档位 = 手部档位 | 联合去噪（视频和手一起生成） |
| 视频干净、手加噪 | 条件拟合（看着观测预测手，即 eval 测的） |

### 验证

同一步数（iter 2000）对比：

| 用例 | 修复前 | 修复后 |
|---|---|---|
| train_00 | 0.65 | **0.11** |
| train_01 | 1.85 ❌ 恶化中 | **0.26** ✅ |
| val_00 | 0.69 | **0.21** |
| val_01 | 2.59 ❌ 恶化中 | **0.55** ✅ |

**之前一直在恶化的两个 case 不再恶化，全部稳定在 1 以下。**
step 0 的数字完全一致（同一份起始权重），对照干净。

### 防复发

`cosmos_framework/model/generator/fk_independent_schedule_test.py`
—— 11 项 AST + 配置检查，无需 GPU。**失败模式是安静的那种**：sigma 算了但没传下去、
或者配置名拼错，训练照跑、指标照降，只是"没变好"。所以要在启动前静态检查。

## 第 3 节：为了找这两个问题，排除过的假设

记录下来，避免重走。**每一条都是做实验排掉的，不是想想就算。**

| # | 假设 | 怎么排的 | 结果 |
|---|---|---|---|
| 1 | checkpoint 没加载对 | 把训练记录的 eval 原样重放 | ❌ 逐位一致（119.90 = 119.90） |
| 2 | 用的是 EMA 权重而非训练权重 | 两套权重分别测 | ❌ 151.4 vs 152.0 |
| 3 | 固定测试样本太难 | 换普通样本测 | ❌ 一样差 |
| 4 | 打包样本数不同 | 造同尺寸的包测 | ❌ 一样差 |
| 5 | 数据掩码有问题 | 直接看掩码 | ❌ 100% 正常 |
| 6 | 某个 σ 档位没学好 | 密集扫 σ | ❌ **完全平坦** |
| 7 | 采样器的 σ 表算错 | 实例化官方采样器比对 | ❌ 5 位小数一致 |
| 8 | 正负号 / 参数传错 | 逐行读代码 + 单元测试 | ❌ 都对 |
| 9 | `fk_loss` 函数本身算错 | 调它和手算比 | ❌ 比值 1.0000000878 |
| 10 | 采样步数不够 | unipc/4 vs euler/16 | ⚠️ 只改善 20%（119.9→94.8），非主因 |
| 11 | 视频**内容**（干净 vs 加噪） | 同状态同 σ 同 ε 的 A/B | ❌ 结果与预测相反 |
| 12 | 视频**时间标记** | 修 A/B 后重跑 | ❌ 240.4 → 240.1，无变化 |
| 13 | 训练集没覆盖 val 的位移范围 | 扫全部 13156 个窗口 | ❌ val_00 在 95.8 分位，训练集有 **549 个**比它更快 |
| 14 | **步数不够** | 500→4000 步看趋势 | ❌ **早就平台**（0.24 → 0.20） |

**第 11、12 条是最被看好的假设，都被干净地推翻了。** 这也说明"在 eval 侧找原因"
这条路走不通 —— 根因在**训练时的条件构造**里。

## 第 4 节：当前状态与剩余的精度问题

四个 case 在 iter 4000 时**全部 < 1 且稳定**：

| case | ratio |
|---|---|
| train_00 | 0.11 |
| train_01 | 0.26 |
| val_00 | 0.20 |
| val_01 | 0.55 |

**剩余的不是 bug，是精度**：一个约 **16% 的"幅度压缩"**。

- 方向余弦 **0.94~0.998**（几乎完美）
- 幅度比 **0.84~1.08**（大位移被压小、小位移被放大）
- 表现：**手型对、方向对，但整只手"移动得不够远"**（大动作尤其明显）
- 误差随步数增长（第 1 步 6.5 mm → 第 32 步 65.9 mm），但**这不是累积** ——
  FK 的预测是**并行的**（32 步一次性输出、都相对第 0 帧），步与步之间没有链条。
  误差增长只是因为**真值本身在长大**（30 → 294 mm，涨 9.7 倍），
  而误差涨 10.1 倍 —— 同比例。

**原因尚未定位。** 已排除步数、数据覆盖范围、固定变换/位姿表示。
剩余候选（都未验证）：数据多样性（仅 10 episode）、特定运动模式特殊、
或均值回归本身是 MSE 损失下的固有行为。

## 第 5 节：操作手册

### 改 scale（数据选点变了才需要）

```bash
python tools/scan_fk_displacement_scale.py     # 拿到新值
# 改 configs/.../action_policy_singlerighthand_edge.py 里的 fk_displacement_scale
PYTHONPATH=. python cosmos_framework/configs/base/experiment/action/posttrain_config/fk_displacement_scale_test.py
```

⚠️ **改了必须新 OUTPUT_ROOT 重训**，旧 checkpoint 不可续训。

### 起训 / 续训

```bash
bash tools/run_fk_retrain.sh                    # 从零
RUN_NAME=<新名> RESUME_FROM=<源 run> MAX_ITER=<目标步> bash tools/run_fk_retrain.sh
```

脚本会：自动选唯一目录名、按算出的需求检查磁盘、判断 checkpoint 是"完整"还是
"只有权重"（决定能否保留 iteration 计数）、打印盯日志和清磁盘的命令。

### 看结果

```bash
tail -f "$(cat /tmp/fk_last_run)"/logs/*.log
```

**判据只有一个：`fk/val_XX/ratio_to_zero`（越小越好，< 1 才算比"猜手不动"强）。**
`train/fk_ade_mm` 的**读数会随 scale 变化，跨 scale 不可比**。
